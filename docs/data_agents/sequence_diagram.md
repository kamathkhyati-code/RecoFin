# Data Sub-graph Sequence Diagram

Two views, both traced against the real code (data_subgraph.py and
recon_platform/graph/build.py), not written from memory.

## 1. Standalone call sequence (run_data_subgraph_by_source)

This is the actual function-call sequence when running the data agents on
their own, with no LangGraph involved.

```mermaid
sequenceDiagram
    participant Caller
    participant DataSubgraph as run_data_subgraph_by_source
    participant Ingestion as ingestion_agent
    participant SourceTool as csv_read_tool / api_fetch_tool / sftp_fetch_tool
    participant FieldMap as field_map_tool
    participant Validation as validate_transactions
    participant Normalization as normalize_transactions
    participant Alias as AliasStore
    participant Gateway as LLMGateway (optional, None by default)

    Caller->>DataSubgraph: named_configs = book and bank source lists
    loop for each named source list
        DataSubgraph->>Ingestion: ingestion_agent with source_configs
        loop for each SourceConfig
            Ingestion->>SourceTool: fetch(location, options)
            SourceTool->>FieldMap: field_map_tool(row, field_map)
            FieldMap-->>SourceTool: remapped row
            SourceTool-->>Ingestion: IngestResult(transactions, issues)
        end
        Ingestion-->>DataSubgraph: transactions, issues, ingestion_metrics
    end
    Note over DataSubgraph: all sources transactions combined for validation
    DataSubgraph->>Validation: validate_transactions(all_transactions, gateway)
    loop 4 deterministic checks
        Validation->>Validation: completeness_tool / dedupe_tool / format_tool / fx_check_tool
    end
    opt row passed every check but has no reference
        Validation->>Gateway: generate(ambiguous_prompt), only if gateway is not None
        Gateway-->>Validation: LLMVerdict (guardrailed)
    end
    Validation-->>DataSubgraph: list of ValidationFinding
    Note over DataSubgraph: normalization runs per-name so book/bank stay separate
    loop for each named source raw transactions
        DataSubgraph->>Normalization: normalize_transactions(txns, base, gateway, store)
        Normalization->>Normalization: fx_rate_tool(amount, currency, base)
        Normalization->>Alias: entity_alias_tool(name)
        Alias-->>Normalization: canonical name, cached to disk if resolved via gateway
        Normalization->>Normalization: canonicalize_reference(ref)
        Normalization-->>DataSubgraph: normalized Transaction list
    end
    DataSubgraph-->>Caller: transactions, issues, validation_findings, book and bank transactions
```

## 2. Wired into the full compiled graph

Same three stages, but as LangGraph nodes composed with everyone elses
nodes (recon_platform/graph/build.py). This is what actually runs via
build_graph().invoke(...) in the demo/production path, including the
validation-failure retry loop and the escalation branch to human review.

```mermaid
flowchart TD
    START([START]) --> supervisor
    supervisor --> ingestion["ingestion_node: A11 real ingest_sources_with_metrics, book/bank kept separate"]
    ingestion --> validation["validation_node: A11/A14 validate_transactions, tags severity error/warning/review"]
    validation -- "critical batch-level issue, retry_count under limit" --> ingestion
    validation -- "row needs human review, severity=review" --> resolution
    validation -- "clean, or retries exhausted" --> normalization["normalization_node: A11 normalize_transactions, module-level AliasStore"]
    normalization --> matching["matching_node: B11 reasoning sub-graph, not covered in this doc"]
    matching -- exceptions found --> resolution["resolution_node: B9/B11 HITL escalation"]
    matching -- no exceptions --> consolidation
    resolution --> consolidation["consolidation_node: C11/C14 build ReconReport"]
    consolidation -- close_ready --> learning["learning_node"]
    consolidation -- not close_ready --> END2([END])
    learning --> END([END])
```

A rendered PNG of this same full graph already exists at
docs/graph/recon_graph.png (generated by scripts_render_graph.py) -- this
docs flowchart above is a hand-maintained, more detailed version scoped to
explain the data sub-graphs gates specifically.
